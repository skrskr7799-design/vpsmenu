# vpsmenu

Маленькая терминальная панель управления VPS на **Ubuntu 22.04 / 24.04**: Dashboard, настройка безопасности, Docker, Remnanode, профили серверов. Один файл на Bash без зависимостей: ставится как команда `vpsmenu` и обновляет себя из этого репозитория.

## Установка

Подставь свой ник и название репозитория. На свежем VPS (под root):

```bash
apt-get update -qq && apt-get install -y -qq curl && curl -fsSL https://raw.githubusercontent.com/ВАШ_НИК/vpsmenu/main/vpsmenu.sh -o /usr/local/bin/vpsmenu && chmod +x /usr/local/bin/vpsmenu && vpsmenu
```

**Если работаешь под обычным пользователем с sudo:**

Скопируй и выполни команду целиком:

```bash
sudo apt-get update -qq && sudo apt-get install -y -qq curl && sudo curl -fsSL https://raw.githubusercontent.com/skrskr7799-design/vpsmenu/main/vpsmenu.sh -o /usr/local/bin/vpsmenu && sudo chmod +x /usr/local/bin/vpsmenu && vpsmenu
```

После установки запускай панель командой `vpsmenu` из любого каталога.

Перед публикацией впиши репозиторий в `src/10-constants.sh` и пересобери (`bash build.sh`):

```bash
readonly DEFAULT_REPO="ВАШ_НИК/vpsmenu"
```

## Управление

- Пункты меню выбираются **одной клавишей**, Enter не нужен. Двузначные пункты (10–14) вводятся двумя цифрами подряд.
- `0`, `Esc` или `q` — назад (в главном меню — выход). Буквы — горячие клавиши (`d` — Dashboard, `s` — Service Manager, `a` — Security Audit, `n` — NetBird).
- Подтверждения: `y`/`n` или `д`/`н`, Enter — вариант по умолчанию.
- Цвета отключаются переменной `NO_COLOR=1`. На узких терминалах (телефон) включается компактный режим.

## Dashboard

Клавиша `d` в главном меню или `vpsmenu --dashboard` (работает и без терминала, например по SSH-команде). Показывает реальные данные: CPU, RAM, swap и диски со шкалами, сеть и трафик, упавшие службы systemd, контейнеры Docker и Remnanode, безопасность (сессии, неудачные входы по SSH за сутки и главные источники, баны fail2ban, обновления безопасности, нужна ли перезагрузка). `r` — обновить, `a` — автообновление каждые 5 с, `q` — назад.

## NetBird

Клавиша `n` в главном меню. Приватная сеть на WireGuard: установка официальным скриптом `pkgs.netbird.io`, подключение по **setup-ключу** (создаётся в панели NetBird: Setup Keys). Ключ вводится скрыто и передаётся клиенту через переменную окружения `NB_SETUP_KEY`, поэтому нигде не сохраняется и не виден в списке процессов; для своего сервера можно указать Management URL.

Главное — **«SSH только через NetBird»**: шаг 1 добавляет правило UFW для интерфейса NetBird (публичный SSH пока открыт), ты проверяешь вход во втором окне, шаг 2 закрывает публичный SSH. Есть откат. Удаление NetBird блокируется, пока SSH закрыт для интернета. Если у хостера есть внешний файрвол, публичный порт нужно закрыть и там.

## Security Audit

Клавиша `a` в главном меню. **Quick Scan** — основные проверки за пару секунд, **Full Scan** — плюс права на файлы, Docker, обслуживание. Проверяется SSH, файрвол и fail2ban, пользователи, открытые порты (с учётом правил UFW), Docker (в том числе порты, опубликованные в обход UFW), обновления, службы, права на ключи и секреты.

Оценка 0–100 считается по прозрачным правилам: старт со 100, штраф за находку (критичная -20, высокая -10, средняя -5, низкая -2), у каждой строки отчёта виден штраф. Для открытых портов хоста и портов Docker действуют лимиты по -15. Принятые риски, справочные и пропущенные пункты не учитываются. Оценка — ориентир по настройкам, а не проверка на взлом.

Из отчёта можно сразу **исправить** находку (переход в нужный пункт меню или выставление прав), **принять риск** либо отметить порт «ожидаемым» (например, порт ноды), **сохранить отчёт** и переключить режим. Для скриптов: `vpsmenu --audit [quick|full]` печатает отчёт без цветов, код выхода 0 — порядок, 1 — есть высокие, 2 — есть критичные.

## Service Manager

Клавиша `s` в главном меню. Универсальный модуль для systemd: все службы, работающие, упавшие; запуск, остановка, перезапуск, автозапуск, журнал, карточка службы. Служба выбирается **из списка** (по 9 на странице): `n`/`p` или стрелки — страницы, `f` — фильтр, `/` — поиск, цифра — выбор. Критичные службы (SSH, сеть, Docker, UFW, системные) защищены: остановка и отключение требуют ввести «да». После запуска проверяется результат, при сбое показывается журнал.

## Watchdog для Remnanode

Меню **7 → 14**. Если нода упала, в главном меню и в Dashboard появляется красная пометка со временем падения. Автоперезапуск настраивается отдельно и **по умолчанию выключен**; можно задать интервал проверки (1–60 мин) и максимум попыток подряд. Если ты сам остановил ноду из меню, watchdog её не трогает. Работает через systemd-таймер (`vpsmenu --watchdog`).

## Профили серверов

Меню **13**. Профиль — набор ответов для настройки нового сервера. Можно выбрать готовый (`node-full`, `minimal`, `hardened`), пройти анкету с вопросами и подсказками, сохранить свой профиль в `/etc/vpsmenu/profiles/`.

Свои профили можно хранить в репозитории: `profiles/<имя>.conf` (пример — `profiles/node-full.conf`). На сервере: **13 → 4**, ввести имя. Профиль читается как обычный текст `КЛЮЧ=значение`, ничего не исполняется, значения проверяются. Шаги, влияющие на доступ (запрет root, вход по ключам), как и в обычном меню, требуют подтверждения.

## Обновление

- Из меню: **12 → 1**, либо командой `vpsmenu --update`.
- Раз в сутки скрипт тихо проверяет репозиторий и показывает в главном меню, если вышла новая версия.
- Перед заменой сохраняется копия текущей версии в `/var/backups/vpsmenu/` (последние 5). Откат: **12 → 2**.
- Скачанный файл проверяется (`bash -n`, маркер vpsmenu, версия); битый файл не устанавливается.

## Безопасность и защита от ошибок

- Опасные операции (запрет root, отключение пароля, закрытие старого порта SSH) требуют ввести «да» после проверки входа во втором окне.
- Конфиги сначала проверяются (`sshd -t`, `fail2ban-client -t`, валидация JSON), при ошибке — автоматический откат.
- Перед запретом root и отключением пароля проверяется, что ты не останешься без доступа.
- Бэкапы лежат в `/var/backups/vpsmenu/` с правами только для root: внутри могут быть ключи и секреты.
- Журнал действий: `/var/log/vpsmenu.log`.

Первый раз лучше прогнать на тестовом сервере.

## Структура репозитория

```
vpsmenu.sh          собранный файл — его ставят и обновляют серверы (не правится руками)
build.sh            сборка vpsmenu.sh из src/ (bash build.sh, проверка для CI: bash build.sh --check)
src/                исходники по модулям: ui, input, ssh, ufw, docker, dashboard, main …
tests/               автотесты: unit.sh (чистые функции, аудит, Service Manager), netbird.sh, run.sh (запуск всех), stubs/ — заглушки команд
profiles/           примеры профилей
.github/workflows/  проверки CI
```

Модули собираются по порядку имён файлов (`00-header.sh` … `99-main.sh`).

## Разработка и выпуск версии

1. Правишь исходники в `src/`.
2. Поднимаешь `APP_VERSION` в `src/10-constants.sh` и добавляешь раздел `## <версия>` в начало `CHANGELOG.md` (его первые строки показываются при обновлении).
3. `bash build.sh && bash tests/run.sh` — собрать и проверить.
4. Коммитишь **и `src/`, и собранный `vpsmenu.sh`**, `git push`. На серверах появится уведомление, обновление ставится из меню.

CI проверяет: собранный файл соответствует `src/`, синтаксис, ShellCheck, автотесты, заполненный `DEFAULT_REPO`, совпадение версии с CHANGELOG.

Для тестов функции подключаются без запуска: `VPSMENU_SOURCE_ONLY=1 source ./vpsmenu.sh`. Пути (`VPSMENU_LOG_FILE`, `VPSMENU_CONF_FILE`, `VPSMENU_BACKUP_DIR`, `VPSMENU_STATE_DIR`, `VPSMENU_PROFILE_DIR`) переопределяются переменными окружения. Для проверки обновления на локальном сервере можно подменить источник: `VPSMENU_RAW_BASE=http://127.0.0.1:8099 vpsmenu`.
