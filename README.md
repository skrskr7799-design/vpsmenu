# vpsmenu

**Интерактивная Bash-панель для настройки, обслуживания и диагностики VPS на Ubuntu.**

vpsmenu объединяет в одном терминальном меню базовое администрирование сервера, инструменты безопасности, управление службами и контейнерами, диагностику журналов и дискового пространства.

- **Текущая версия:** 3.5.0
- **Целевая платформа:** Ubuntu 22.04 / 24.04
- **Интерфейс:** интерактивное TUI-меню
- **Формат поставки:** один собранный Bash-файл — `vpsmenu.sh`
- **Репозиторий:** [skrskr7799-design/vpsmenu](https://github.com/skrskr7799-design/vpsmenu)
- **История изменений:** [CHANGELOG.md](CHANGELOG.md)

## Возможности

| Направление | Что входит |
|---|---|
| Мониторинг | Dashboard с ресурсами сервера, сетевой активностью, состоянием служб и контейнеров |
| Безопасность | Security Audit, SSH hardening, UFW, nftables, Fail2ban |
| Управление | Пользователи и sudo, службы systemd, Docker, Remnanode |
| Диагностика | Анализ журналов, дисков и inode, IPv6, сетевые проверки, Speedtest |
| Сеть | NetBird, управление IPv6, диагностика портов и доступности ресурсов |
| Обслуживание | Обновление системы, BBR, swap, NTP, автоматические обновления безопасности |
| Автоматизация | Мастер настройки, профили серверов, watchdog для Remnanode |
| Самообслуживание | Обновление vpsmenu из GitHub, резервная копия версии и откат |

vpsmenu рассчитан на выполнение административных задач из одного интерфейса. Это не система мониторинга 24/7 и не замена резервному копированию, внешнему firewall или полноценному аудиту безопасности.

## Требования

- Ubuntu 22.04 или Ubuntu 24.04 — целевые версии проекта.
- Система с работающим **systemd**.
- Права **root**. При запуске от обычного пользователя скрипт попробует повторно запуститься через `sudo`.
- Интерактивный терминал для основного меню.
- Доступ в интернет для установки дополнительных компонентов, загрузки обновлений и работы сетевых функций.

Скрипт написан на Bash и поставляется одним собранным файлом. Отдельные языковые среды вроде Python, Node.js или Go для запуска самого меню устанавливать не требуется. Некоторые функции используют системные утилиты Ubuntu или устанавливают необходимые пакеты по запросу.

На других дистрибутивах скрипт может предупредить о неподдерживаемой системе и запросить подтверждение продолжения. **systemd обязателен**.

## Установка

Команды ниже устанавливают актуальный собранный скрипт из ветки `main` непосредственно в `/usr/local/bin/vpsmenu`.

```bash
sudo apt-get update
sudo apt-get install -y curl ca-certificates

sudo curl -fsSL \
  https://raw.githubusercontent.com/skrskr7799-design/vpsmenu/main/vpsmenu.sh \
  -o /usr/local/bin/vpsmenu

sudo chmod 0755 /usr/local/bin/vpsmenu
sudo vpsmenu
```

После установки панель запускается командой:

```bash
sudo vpsmenu
```

Проверить установленную версию:

```bash
sudo vpsmenu --version
```

> **Совет:** перед применением настроек SSH или firewall убедись, что у тебя есть доступ к консоли VPS через панель хостера. Это позволит восстановить доступ, если сетевые правила будут настроены неправильно.

## Первый запуск

При первом запуске vpsmenu проверяет операционную систему, права и окружение, затем открывает главное меню.

Если скрипт был запущен из временного файла, он предложит установить текущую копию как системную команду. При установке вручную в `/usr/local/bin/vpsmenu`, как в инструкции выше, этот шаг не требуется.

Главный экран в обычном режиме показывает краткий статус SSH, IPv6, UFW, nftables, Fail2ban, Docker, Remnanode и основных параметров обслуживания. На узких терминалах интерфейс автоматически переключается в компактный режим.

## Управление меню

Пункты меню выбираются **одной клавишей — нажимать Enter не нужно**. Для двузначных пунктов (10–14) введи две цифры подряд.

- `0` — назад во вложенном меню или выход из главного.
- `Esc` — назад во вложенном меню.
- `q` — выход из главного меню; во вложенных меню также воспринимается как возврат.
- `y` / `n` или `д` / `н` — подтверждение или отказ.
- Enter в запросе подтверждения выбирает вариант по умолчанию.
- Для особо опасных операций может потребоваться ввести подтверждающее слово целиком.

## Модули

### Dashboard

**Быстрый обзор состояния VPS.** Открывается клавишей `d` или командой `vpsmenu --dashboard`.

Показывает:

- загрузку CPU, использование RAM и swap;
- заполнение файловых систем;
- сетевые интерфейсы и трафик;
- упавшие службы systemd;
- состояние Docker и Remnanode;
- активные сессии и неудачные попытки входа по SSH;
- состояние Fail2ban, обновлений безопасности и необходимость перезагрузки.

В интерактивном Dashboard:
- `r` — обновить данные;
- `a` — включить или выключить автообновление с интервалом 5 секунд;
- `q` — вернуться назад.

Одноразовый режим `--dashboard` выводит снимок состояния и завершает работу. Он подходит для запуска без интерактивного меню.

### Security Audit

**Проверка основных настроек безопасности сервера.** Горячая клавиша — `a`.

Доступны два режима:

- **Quick Scan** — основные проверки, рассчитанные на быстрый запуск.
- **Full Scan** — расширенная проверка, включая дополнительные параметры пользователей, файлов, Docker и обслуживания.

Проверяются, в частности:

- настройки SSH и возможность входа под root;
- firewall и правила доступа;
- открытые порты, в том числе опубликованные Docker-порты;
- пользователи и права;
- Fail2ban;
- службы и обновления;
- отдельные параметры Docker и системной конфигурации.

Результат включает оценку от 0 до 100 и список находок с уровнями важности. Оценка рассчитывается по правилам самого модуля и служит **ориентиром по конфигурации**, а не доказательством отсутствия взлома или уязвимостей.

Из отчёта можно перейти к исправлению поддерживаемой находки, принять риск, добавить ожидаемый порт или сохранить отчёт. Исключения учитываются при последующих проверках.

Запуск из командной строки:

```bash
sudo vpsmenu --audit
sudo vpsmenu --audit quick
sudo vpsmenu --audit full
```

Коды завершения:
- `0` — критичных и высоких находок нет;
- `1` — обнаружены находки высокого уровня;
- `2` — обнаружены критичные находки;
- некорректный режим возвращает код ошибки использования.

### Service Manager

**Управление службами systemd** — клавиша `s`.

Возможности:

- просмотр всех, работающих и упавших служб;
- поиск и фильтрация списка;
- запуск, остановка и перезапуск;
- включение и отключение автозапуска;
- просмотр журнала и подробного статуса;
- сброс состояния failed через `systemctl reset-failed`;
- выполнение `systemctl daemon-reload`.

Службы выбираются из списка. Для навигации доступны страницы, фильтр и поиск. Для критичных системных служб предусмотрено дополнительное подтверждение опасных действий.

### Storage Analyzer

**Поиск причин заполнения диска и безопасная очистка** — клавиша `m`.

Модуль помогает найти, какие каталоги и данные занимают место:

- использование файловых систем и inode;
- крупные каталоги и файлы;
- проводник по каталогам;
- журналы systemd и архивы логов;
- Docker: образы, тома, кэш и логи контейнеров;
- кэш apt и старые пакеты/ядра;
- старые ревизии Snap и дампы падений.

Для поддерживаемых операций очистки предусмотрен предварительный просмотр и подтверждение. В зависимости от выбранного действия можно удалить старые архивы журналов, очистить крупный лог, выполнить vacuum журнала systemd, почистить Docker или системные кэши.

Модуль также умеет сохранять диагностический отчёт в `/var/backups/vpsmenu/`. Отчёт создаётся с правами доступа `600`.

> **Важно:** глубокая очистка Docker может удалить образы, которые сейчас не используются контейнерами. Перед подтверждением внимательно читай описание выбранного режима.

### Log Analyzer

**Единый центр анализа журналов** — клавиша `l`.

Источники событий:

- system journal;
- kernel;
- SSH-аутентификация;
- упавшие службы systemd и их журналы;
- логи Docker-контейнеров;
- Remnanode.

Фильтры анализа:

- период: 1 час, 6 часов, 24 часа, 3 дня или 7 дней;
- только ошибки либо ошибки вместе с предупреждениями.

Повторяющиеся события группируются по источнику, службе и нормализованному сообщению. Для групп отображаются количество повторов, первое и последнее время появления и до трёх примеров. Для события можно открыть временной контекст вокруг первого появления.

Успешные и неудачные SSH-аутентификации учитываются отдельно. Успешные входы отображаются как информационные события, а не как ошибки.

Модуль показывает состояние каждого источника: например, пустой журнал, недоступность, нехватку прав, тайм-аут или ошибку запроса. Это помогает отличить отсутствие событий от невозможности прочитать источник.

TXT-отчёт сохраняется в `/var/backups/vpsmenu/` с правами `600`. Log Analyzer работает в режиме чтения: он не исправляет найденные проблемы и не перезапускает службы автоматически.

### NetBird

**Управление приватной сетью на базе NetBird/WireGuard** — клавиша `n`.

Основные действия:

- установка NetBird;
- подключение к сети по setup key;
- просмотр статуса;
- отключение и повторное подключение;
- обновление и удаление клиента;
- просмотр журнала.

Setup key создаётся в панели управления NetBird. При подключении ключ вводится скрыто и передаётся клиенту через переменную окружения `NB_SETUP_KEY`. Для собственного Management-сервера можно указать Management URL.

#### SSH только через NetBird

Ограничение публичного SSH выполняется в два этапа:

1. Добавить разрешающее правило для SSH через интерфейс NetBird. Публичный SSH на этом этапе остаётся доступным.
2. Проверить подключение по NetBird во втором терминальном окне и только после этого закрыть публичный SSH.

Предусмотрен откат, возвращающий публичный SSH-доступ.

> **Не пропускай проверку на втором этапе.** Если закрыть публичный SSH до проверки соединения через NetBird, можно потерять удалённый доступ. Если у хостера есть внешний firewall или security group, правила нужно проверить и там. Удаление NetBird блокируется, пока публичный SSH закрыт.

### Пользователи и SSH

#### Пользователи

Раздел `1` позволяет:

- создавать пользователей с правами sudo;
- просматривать список пользователей;
- проверять и изменять права sudo;
- сбрасывать пароль и блокировать/разблокировать парольную учётную запись;
- добавлять и удалять SSH-ключи;
- удалять пользователей.

#### SSH

Раздел `2` предназначен для базового усиления SSH:

- запрет входа под root;
- добавление публичного ключа пользователю;
- отключение входа по паролю;
- возврат парольной аутентификации;
- добавление нового SSH-порта;
- закрытие старого порта после проверки нового;
- просмотр эффективных параметров SSH;
- откат некоторых изменений из резервной копии.

Перед изменением порта или отключением способа входа обязательно проверь новое подключение в отдельной SSH-сессии. Не закрывай текущую рабочую сессию, пока не убедишься, что новая работает.

### Сетевые фильтры и защита

| Раздел | Что делает |
|---|---|
| UFW (`3`) | Установка и настройка, определение SSH-порта, открытие/удаление правил, логирование |
| nftables (`4`) | Установка и запуск, просмотр правил, проверка синтаксиса конфигурации |
| Fail2ban (`5`) | Установка, настройка jail для SSH, статус, разбан IP и просмотр журналов |
| IPv6 (`9 → 8`) | Включение/выключение IPv6, локальная проверка адресов и маршрута, тест подключения |

При настройке firewall учитывай, что правила UFW, nftables, Docker и внешний firewall хостера могут влиять друг на друга. Особенно внимательно проверяй SSH-порт, прежде чем закрывать доступ.

### Docker и Remnanode

#### Docker

Раздел `6` позволяет установить Docker, проверить состояние, настроить ротацию логов контейнеров, просмотреть контейнеры и использование ресурсов, а также освободить место.

Для очистки предусмотрены два варианта:

- **Безопасный** — остановленные контейнеры, неиспользуемые сети, неиспользуемые образы и кэш сборки.
- **Глубокий** — дополнительно все образы, не используемые контейнерами.

Перед очисткой проверяй выбранный режим: удалённые образы могут понадобиться для повторного запуска контейнеров без новой загрузки.

#### Remnanode

Раздел `7` предназначен для управления Remnanode в Docker Compose.

Доступны:

- первичная настройка каталога и compose-файла;
- запуск, остановка и перезапуск;
- обновление образов и перезапуск;
- просмотр логов контейнера;
- просмотр `xlogs` и `xerrors`;
- вход в контейнер через shell;
- резервное копирование и восстановление конфигураций;
- watchdog.

Каталог Remnanode по умолчанию: `/opt/remnanode`.

#### Watchdog

Watchdog контролирует состояние контейнера Remnanode через systemd timer. Он может показывать события падения и, если отдельно включить соответствующую настройку, выполнять автоматический перезапуск.

Автоперезапуск по умолчанию выключен. Можно задать интервал проверки и максимальное число последовательных попыток. Если нода была остановлена вручную через меню, watchdog учитывает это состояние и не должен запускать её самовольно.

### Обслуживание и диагностика сети

#### Оптимизация и обслуживание

Раздел `9` включает:

- обновление пакетов системы;
- настройку часового пояса и NTP;
- включение BBR;
- создание и настройку swap;
- настройку автоматических обновлений безопасности;
- резервное копирование конфигураций;
- управление IPv6.

Эти операции меняют системную конфигурацию. Перед применением проверяй параметры и учитывай особенности конкретного VPS.

#### WARP Native

Раздел `8` запускает установщик WARP Native и проверяет, обнаружена ли уже установка.

#### Диагностика сети

Раздел `14` включает:

- Speedtest;
- установку и проверку speedtest-cli;
- ping до нескольких публичных адресов;
- проверку доступности GitHub, Docker Hub и репозиториев пакетов;
- определение внешних IPv4/IPv6-адресов;
- просмотр прослушиваемых портов.

### Мастер и профили серверов

#### Мастер быстрой настройки

Раздел `10` последовательно проводит через основные этапы настройки VPS. Любой шаг можно пропустить.

#### Профили серверов

Раздел `13` позволяет применить готовый профиль, настроить параметры вручную и сохранить собственный набор настроек.

Встроенные варианты:

- `node-full`;
- `minimal`;
- `hardened`.

Профили из репозитория хранятся в `profiles/<имя>.conf`. Пример — [profiles/node-full.conf](profiles/node-full.conf).

Файл профиля представляет собой набор значений `КЛЮЧ=значение`: он разбирается как данные и не исполняется как shell-скрипт. Значения проходят проверку перед применением. Действия, которые могут повлиять на удалённый доступ, требуют подтверждения.

## Обновление и откат

Обновить установленный скрипт можно двумя способами:

- через меню: **12 → 1**;
- из командной строки: `sudo vpsmenu --update`.

При обновлении vpsmenu:

1. Загружает файл из настроенного GitHub-репозитория.
2. Проверяет структуру скрипта и наличие версии.
3. Сравнивает версии и показывает соответствующий раздел changelog.
4. Перед заменой сохраняет текущую копию.
5. Устанавливает новую версию только после подтверждения.

Резервные копии скрипта хранятся в `/var/backups/vpsmenu/`; сохраняются последние пять копий. Откат доступен через меню **12 → 2**.

При запуске меню репозиторий проверяется не чаще одного раза в сутки. Если доступна более новая версия, vpsmenu показывает уведомление. Автоматической установки без подтверждения нет.

По умолчанию источник обновлений — этот репозиторий и ветка `main`. Настройки можно изменить в меню **12 → 3**.

## Безопасность и важные замечания

vpsmenu выполняет административные действия с правами root. Используй его осознанно и сначала проверяй изменения на тестовом VPS.

- **SSH и firewall.** Не отключай текущий способ доступа, пока не проверено новое подключение. По возможности держи открытой консоль хостера.
- **Опасные действия.** Критичные операции требуют явного подтверждения; отдельные действия требуют ввести слово целиком.
- **Проверка конфигураций.** Перед применением ряда изменений скрипт проверяет синтаксис конфигурации и предусматривает откат при ошибке.
- **Резервные копии.** Файлы в `/var/backups/vpsmenu/` могут содержать конфигурации, ключи и секреты. Каталог предназначен для root; не публикуй его содержимое.
- **Логи.** Журнал действий vpsmenu находится в `/var/log/vpsmenu.log`.
- **Внешний firewall.** Правила в панели провайдера VPS настраиваются отдельно и не заменяются UFW или nftables.
- **Оценка Security Audit.** Это проверка выбранных конфигурационных признаков, а не полноценный pentest и не гарантия безопасности.

Перед очисткой Docker, изменением SSH или сетевых правил внимательно читай описание операции и её подтверждение.

## Командная строка

```text
vpsmenu                  Запустить интерактивное меню
vpsmenu --help           Показать справку
vpsmenu --version        Показать версию
vpsmenu --install        Установить текущий файл в /usr/local/bin/vpsmenu
vpsmenu --update         Проверить и установить обновление из GitHub
vpsmenu --dashboard      Вывести Dashboard один раз и завершить работу
vpsmenu --audit          Запустить Security Audit (Quick Scan)
vpsmenu --audit quick    Запустить Quick Scan
vpsmenu --audit full     Запустить Full Scan
vpsmenu --watchdog       Выполнить одну проверку Remnanode (служебный режим)
```

Для запуска команд от обычного пользователя используй `sudo`, например:

```bash
sudo vpsmenu --audit full
```

Основное интерактивное меню требует терминал. Режимы `--dashboard` и `--audit` можно использовать в сценариях автоматизации без интерактивного меню.

## Файлы и каталоги

| Путь | Назначение |
|---|---|
| `/usr/local/bin/vpsmenu` | Установленный исполняемый файл |
| `/etc/vpsmenu.conf` | Конфигурация vpsmenu и параметры источника обновлений |
| `/var/log/vpsmenu.log` | Журнал действий |
| `/var/backups/vpsmenu/` | Резервные копии и диагностические отчёты |
| `/var/lib/vpsmenu/` | Состояние и служебные данные |
| `/etc/vpsmenu/profiles/` | Профили сервера |
| `/opt/remnanode/` | Каталог Remnanode по умолчанию |

Некоторые пути можно переопределить переменными окружения при тестировании или специальной установке; обычному пользователю менять их не требуется.

## Разработка и тестирование

В репозитории хранятся исходные модули и собранный файл, который устанавливается на сервер.

```text
vpsmenu/
├── src/                  Исходники Bash-модулей
├── tests/                Автоматические тесты и заглушки команд
├── profiles/             Примеры профилей серверов
├── .github/workflows/    GitHub Actions: lint и CI
├── build.sh              Сборка и проверка собранного файла
├── vpsmenu.sh            Готовый единый скрипт для установки
├── CHANGELOG.md          История изменений
└── README.md             Документация проекта
```

### Локальная сборка

Сборка выполняется из файлов `src/*.sh` в порядке имён:

```bash
bash build.sh
```

Проверить, что закоммиченный `vpsmenu.sh` соответствует исходникам:

```bash
bash build.sh --check
```

**Не редактируй `vpsmenu.sh` вручную.** Изменения вносятся в `src/`, после чего файл пересобирается.

### Тесты и проверки

Запустить весь набор автотестов:

```bash
bash tests/run.sh
```

Дополнительные проверки:

```bash
bash -n vpsmenu.sh
shellcheck -S warning vpsmenu.sh build.sh tests/unit.sh tests/netbird.sh tests/ipv6.sh tests/users.sh tests/storage.sh tests/log.sh
```

GitHub Actions выполняет сборку, проверку синхронизации `src/` и `vpsmenu.sh`, проверку синтаксиса, ShellCheck и автотесты. Также проверяются заполненный `DEFAULT_REPO` и соответствие версии в скрипте заголовку в `CHANGELOG.md`.

Для подключения функций без запуска меню в тестах используется:

```bash
VPSMENU_SOURCE_ONLY=1 source ./vpsmenu.sh
```

В тестовой среде можно переопределить пути через `VPSMENU_LOG_FILE`, `VPSMENU_CONF_FILE`, `VPSMENU_BACKUP_DIR`, `VPSMENU_STATE_DIR`, `VPSMENU_PROFILE_DIR`. Для проверки обновления можно задать `VPSMENU_RAW_BASE`.
