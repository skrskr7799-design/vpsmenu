# vpsmenu

Интерактивное меню для первичной настройки и обслуживания VPS на **Ubuntu 22.04 / 24.04**. Один файл на Bash, без зависимостей: ставится в систему как команда `vpsmenu`, умеет обновлять сам себя из этого репозитория.

## Установка

Подставь свой ник и название репозитория. На свежем VPS (под root):

```bash
apt-get update -qq && apt-get install -y -qq curl && curl -fsSL https://raw.githubusercontent.com/ВАШ_НИК/vpsmenu/main/vpsmenu.sh -o /usr/local/bin/vpsmenu && chmod +x /usr/local/bin/vpsmenu && vpsmenu
```

Под обычным пользователем с sudo добавь `sudo` перед `apt-get`, `curl` и `chmod`. Дальше запуск из любого места: `vpsmenu`.

```bash
sudo apt-get update -qq && sudo apt-get install -y -qq curl && sudo curl -fsSL https://raw.githubusercontent.com/ТВОЙ_НИК/vpsmenu/main/vpsmenu.sh -o /usr/local/bin/vpsmenu && sudo chmod +x /usr/local/bin/vpsmenu && vpsmenu
```


Перед публикацией впиши репозиторий в начало `vpsmenu.sh`:

```bash
readonly DEFAULT_REPO="ВАШ_НИК/vpsmenu"
```

Если оставить `CHANGE_ME/vpsmenu`, скрипт спросит репозиторий при первом обновлении и сохранит его в `/etc/vpsmenu.conf`.

## Что умеет

| Раздел | Возможности |
|---|---|
| Пользователь | создание пользователя с sudo, проверки, копирование SSH-ключей root |
| SSH | запрет входа root, ключи, вход только по ключам, смена порта (два шага), откат |
| UFW | установка, автоопределение порта SSH, открыть порт (в т. ч. для IP), удалить правило, логирование |
| nftables | установка и запуск без потери правил UFW/Docker |
| Fail2ban | установка, мастер настройки jail sshd, разбан, логи |
| Docker | установка, ротация логов, очистка места, контейнеры и ресурсы |
| Remnanode | настройка, запуск, остановка, обновление, логи, `xlogs`, `xerrors`, shell, бэкап и восстановление, **watchdog** |
| WARP Native | запуск установщика с проверкой «уже установлен?» |
| Оптимизация | обновление системы, часовой пояс и NTP, BBR, swap, автообновления безопасности, бэкап конфигов |
| Мастер | все шаги подряд, любой можно пропустить |
| Профили | готовые наборы, настройка вручную, сохранение и загрузка из репозитория |
| Диагностика сети | speedtest-cli, ping, доступность ресурсов, внешний IP, слушающие порты |

## Watchdog для Remnanode

Меню **7 → 14**. Если нода упала, в главном меню появляется красная пометка со временем падения. Автоперезапуск настраивается отдельно и **по умолчанию выключен**; можно включить, задать интервал проверки (1–60 мин) и максимум попыток подряд. Если ты сам остановил ноду из меню, watchdog её не трогает. Работает через systemd-таймер (`vpsmenu --watchdog`).

## Профили серверов

Меню **13**. Профиль — набор ответов для настройки нового сервера. Можно выбрать готовый (`node-full`, `minimal`, `hardened`), пройти анкету с вопросами и подсказками, сохранить свой профиль в `/etc/vpsmenu/profiles/`.

Свои профили можно хранить в репозитории: файл `profiles/<имя>.conf` (пример — `profiles/node-full.conf`). На сервере: **13 → 4**, ввести имя. Профиль читается как обычный текст `КЛЮЧ=значение`, ничего не исполняется, значения проверяются. Шаги, влияющие на доступ (запрет root, вход по ключам), как и в обычном меню, требуют подтверждения.

## Обновление

- Из меню: **12 → 1**, либо командой `vpsmenu --update`.
- Раз в сутки скрипт тихо проверяет репозиторий и показывает в главном меню, если вышла новая версия.
- Перед заменой сохраняется копия текущей версии в `/var/backups/vpsmenu/` (последние 5). Откат: **12 → 2**.
- Скачанный файл проверяется (`bash -n`, маркер vpsmenu, версия); битый файл не устанавливается.

## Безопасность и защита от ошибок

- Опасные операции (запрет root, отключение пароля, закрытие старого порта SSH) требуют ввести «да» после проверки входа во втором окне.
- Конфиги сначала проверяются (`sshd -t`, `fail2ban-client -t`, валидация JSON), при ошибке — автоматический откат.
- Перед запретом root и отключением пароля проверяется, что ты не останешься без доступа.
- Бэкапы лежат в `/var/backups/vpsmenu/` с правами только для root: внутри могут быть ключи и секреты.
- Журнал действий: `/var/log/vpsmenu.log`.

Первый раз лучше прогнать на тестовом сервере.

## Выпуск новой версии

1. Поднять `APP_VERSION` в `vpsmenu.sh`.
2. Добавить раздел `## <версия>` в начало `CHANGELOG.md` (его первые строки показываются при обновлении).
3. `git push` — на серверах появится уведомление, обновление ставится из меню.

GitHub Actions (`.github/workflows/lint.yml`) проверяет синтаксис, ShellCheck, заполненный `DEFAULT_REPO` и совпадение версии с CHANGELOG.

## Разработка

```bash
bash -n vpsmenu.sh
shellcheck -S warning vpsmenu.sh
```

Для проверки обновления на локальном сервере можно подменить источник: `VPSMENU_RAW_BASE=http://127.0.0.1:8099 vpsmenu`.
