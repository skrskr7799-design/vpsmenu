## 3.2.0
- Security Audit (клавиша `a` в главном меню или `vpsmenu --audit [quick|full]`). Quick Scan за пару секунд и Full Scan: SSH, файрвол и fail2ban, пользователи (UID 0, пустые пароли, sudo без пароля), открытые порты с учётом правил UFW, Docker (порты в обход UFW, privileged, docker.sock, открытый API), обновления и перезагрузка, упавшие службы, автообновления, время, параметры ядра, диск, права на ключевые файлы и секреты.
- Оценка по понятным правилам: старт со 100, штраф за каждую находку (критичная -20, высокая -10, средняя -5, низкая -2), лимиты для блоков портов, у каждой строки виден штраф. Экран «Как считается оценка» в самом меню.
- Исправление прямо из отчёта: у находки есть ссылка на нужный пункт меню (или автоматическое выставление прав). «Принять риск» и список «ожидаемых» портов, чтобы намеренно открытые порты ноды не портили оценку.
- Сохранение отчёта в файл (`/var/backups/vpsmenu/audit-*.txt`, права 600), последняя оценка показывается в Dashboard.
- Для автоматизации: `vpsmenu --audit full` печатает отчёт без цветов, код выхода 0 (порядок), 1 (есть высокие), 2 (есть критичные).
- Автотесты аудита: правила оценки, лимиты, разбор `ss`, UFW и Docker, права файлов.

## 3.1.0
- Service Manager (клавиша `s` в главном меню): все службы systemd, работающие, упавшие; запуск, остановка, перезапуск, автозапуск, журнал, карточка службы. Служба выбирается из интерактивного списка (по 9 на странице, фильтры «все / работают / упавшие / не работают / в автозапуске», поиск по названию и описанию), вводить имя вручную не нужно.
- Карточка службы: состояние, автозапуск, PID, память, время запуска, число перезапусков, файл юнита, последние записи журнала; действия, `mask`/`unmask`, полный `systemctl status`.
- Журнал службы: последние 100 записей, только ошибки, с момента загрузки, в реальном времени.
- Защита критичных служб (SSH, сеть, Docker, UFW, системные): остановка, отключение и маскировка требуют ввести «да», перезапуск — подтверждение. После запуска или перезапуска проверяется результат, при сбое показывается журнал.
- `reset-failed` и `daemon-reload` из меню; в Dashboard при упавших службах появилась подсказка.
- Автотесты Service Manager на заглушках `systemctl` и `journalctl` (`tests/stubs/`).

## 3.0.0
- Исходники разбиты на модули: `src/*.sh`, а `vpsmenu.sh` теперь собирается командой `./build.sh`. Для серверов ничего не меняется: ставится и обновляется тот же один файл.
- Новое ядро интерфейса: рамка-заголовок с «хлебными крошками» (`vpsmenu › Remnanode › Watchdog`), выбор пунктов одной клавишей без Enter (двузначные — двумя цифрами подряд), Esc или q — назад, горячие клавиши-буквы, подтверждения одной клавишей (y/n или д/н), «любая клавиша» вместо Enter, шкалы, разделители, спиннер, поддержка `NO_COLOR`, ровное выравнивание кириллицы, компактный режим для узких терминалов (телефон).
- Dashboard (клавиша `d` в главном меню или `vpsmenu --dashboard`): CPU, RAM, swap и диски со шкалами, сеть и трафик, упавшие службы, контейнеры Docker и состояние Remnanode, безопасность (сессии, неудачные входы по SSH за сутки и главные источники, баны fail2ban, обновления безопасности, перезагрузка). Обновление по клавише `r`, автообновление каждые 5 с по клавише `a`.
- Автотесты (`tests/unit.sh`) и проверка в CI, что собранный `vpsmenu.sh` соответствует `src/`.

## 2.0.0
- Самообновление из GitHub: меню «Сам скрипт» → «Обновить», либо `vpsmenu --update`. Перед заменой сохраняется копия текущей версии, есть откат. Раз в сутки скрипт тихо проверяет, не вышла ли новая версия.

- Remnanode: логи xray (`xlogs`, `xerrors`), консоль контейнера, бэкап и восстановление конфигов.

- Панель статусов: порт SSH, вход по паролю, BBR, swap, автообновления.
